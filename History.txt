=== 1.6.0 (in progress)
Archetype Model validation: constraint nodes can now check values and
their own specialisation conformance instead of raising
NotImplementedError or performing no real check at all.

* All eight C_PRIMITIVE subtypes (CBoolean, CInteger, CReal, CString,
  CDate, CTime, CDateTime, CDuration) implement valid_value?, honouring
  range/list/pattern constraints and, for the date/time family, each
  field's ValidityKind (MANDATORY/OPTIONAL/DISALLOWED). CDate/CTime/
  CDateTime#valid_value? accept either an RM DV_DATE/DV_TIME/DV_DATE_TIME
  or a plain ISO8601 string. CInteger and CString's consistency checks no
  longer reject a fully unconstrained node (range/list/pattern all nil);
  previously only CInteger's, and not CString's, allowed this -
  BREAKING: CString.new with all three nil now succeeds instead of
  raising.
* Fixed CDuration#initialize silently discarding the
  years_allowed/months_allowed/weeks_allowed/days_allowed/hours_allowed/
  minutes_allowed/seconds_allowed/fractional_seconds_allowed keyword
  arguments - they were declared as attr_accessor but never read from
  args, so e.g. CDuration.new(:weeks_allowed => false) had no effect.
* New Interval#subset_of?(other): true when every value in self is also
  in other, accounting for unbounded ends and boundary inclusivity. Used
  to implement real specialisation conformance checks.
* CObject#node_conforms_to?(other), CAttribute#node_conforms_to?(other)
  and CMultipleAttribute#node_conforms_to?(other) now perform the actual
  AOM conformance rules instead of inheriting ArchetypeConstraint's
  generic path-prefix check: node_id specialisation (at0001.1 conforms to
  at0001), rm_type_name equality (RM subtype tolerance is deferred until
  the RM type-name helper lands), and occurrences/existence/cardinality
  narrowing (via Interval#subset_of?, with a nil/unconstrained side
  treated as "matches anything" on the parent and "does not narrow
  anything" on the child).
* New OpenEHR::RM.class_for(type_name) / type_name_of(class_or_instance) /
  subtype_of?(class_or_instance, type_name) (lib/openehr/rm/type_name.rb):
  looks up the RM class for a spec type name (or vice versa) and checks
  RM inheritance, by walking the OpenEHR::RM module tree once and
  memoizing a name -> class registry. Accepts UPPER_SNAKE, CamelCase or
  lower_snake input, since rm_type_name is stored in different casings in
  different places in this codebase (the ADL/OPT parsers always produce
  UPPER_SNAKE; some CDomainType constructors hardcode CamelCase).
* CCodePhrase, CDvOrdinal, CDvQuantity (+ its CQuantityItem#matches?) and
  CDvState all gained valid_value?, checking a CODE_PHRASE against
  terminology_id/code_list, a DV_ORDINAL against the value/symbol list,
  a DV_QUANTITY against the per-unit magnitude/precision ranges, and a
  DV_STATE's coded value plus is_terminal? against the constraint's
  StateMachine, respectively.
* CComplexObject#valid_value?(rm_instance) is now a real recursive
  validator instead of raising NotImplementedError: rm_type_name
  conformance (RM subtypes accepted, via OpenEHR::RM.subtype_of?),
  archetype_node_id matching when this node specifies one,
  attribute-by-attribute existence checking, CMultipleAttribute
  cardinality plus per-child-alternative occurrences counting, and
  recursion into each matched attribute value. ArchetypeSlot,
  ArchetypeInternalRef and ConstraintRef children are accepted
  permissively for now (v1 does not resolve slot-fillers or internal
  references - documented limitation).
* CComplexObject#default_value builds the minimal RM instance satisfying
  a node's mandatory constraints (existence lower >= 1 attributes only,
  each attribute's first child alternative's own default_value,
  CMultipleAttribute getting cardinality.interval.lower copies) via
  OpenEHR::RM.class_for; returns nil (rather than raising) whenever a
  mandatory field has no derivable default, since no minimal instance can
  be built in that case.
* The ADL parser now retains the parent archetype id from a specialise
  header instead of discarding it - Archetype#parent_archetype_id is
  populated for specialised archetypes (previously always nil regardless
  of the source ADL).
* Archetype's nine structural-validity methods (physical_paths,
  logical_paths, specialisation_depth, is_specialised?, node_ids_valid?,
  constraint_references_valid?, internal_references_valid?,
  previous_version, is_valid?) all had empty bodies (returning nil
  unconditionally) and now have real implementations: physical_paths/
  logical_paths walk the definition tree (the latter substituting each
  at/ac/id-code predicate with its ontology term text); node_ids_valid?
  checks every node_id is syntactically well-formed and defined in the
  ontology; constraint_references_valid?/internal_references_valid? check
  ConstraintRef/ArchetypeInternalRef targets resolve; is_specialised?/
  specialisation_depth use the newly-retained parent_archetype_id and the
  ontology's own specialisation_depth (falling back to the archetype_id's
  domain_concept suffix); is_valid? composes the three structural checks.
  previous_version stays nil - this gem does not parse ADL revision
  history. The typo'd node_ids_vaild? is kept as a deprecated alias.
* New OpenEHR::Parser::ArchetypeValidator, wiring up the VARID..VDFPT
  archetype-validity rules (exception.rb's Validation error classes were
  defined but never required or used by anything). #errors returns every
  violated rule, #valid? and #validate! (raising the first violation) are
  built on top. #validate_instance(rm_root) separately checks an RM
  instance against the archetype's definition, returning a path-annotated
  InstanceNonConformant (path resolved via the target's own
  path_of_item - the PATHABLE navigation method from 1.4.0) when it does
  not conform. ADLParser#parse gained a validate: keyword (default false,
  preserving existing behaviour) to opt into raising via the validator
  after parsing.
* CComplexObject#find_violation(value): a diagnostic counterpart to
  valid_value? used by ArchetypeValidator#validate_instance, returning
  the first [failing_constraint_node, failing_rm_value] pair found
  instead of a bare boolean.
* The ADL parser now retains the invariant section's assertions
  (previously parsed and then discarded) as Archetype#invariants, an
  array of real Assertion objects (already built by the existing
  assertion/boolean_expression grammar rules - only the archetype-level
  wiring was missing).
* Fixed two further ADL grammar bugs found while exercising the above:
  a tagged invariant/assertion's tag (e.g. "inv1:" in "inv1:1>0") crashed
  with NoMethodError instead of being captured, from calling .value on a
  plain (label-less) sequence node two levels removed from the actual
  identifier; and any_identifier's lowercase-identifier alternative
  crashed with "uninitialized constant V_ATTRIBUTE_IDENTIFIER" because
  Ruby parses a bare ALL-CAPS rule-name reference as a constant, not a
  method call - both are fixed with explicit lower-case labels.
* Fixed OpenEHR::Path::AT_CODE requiring 4+ digits before an optional
  specialisation suffix (at\d{4,}(\.\d+)*) - real ADL 1.4 archetypes use
  a short at0.N form (e.g. at0.2) for nodes newly introduced by a
  specialisation, which the stricter pattern rejected as an invalid path.

=== 1.5.0 (in progress)
RM 1.0.2 behavioral completeness and Factory coverage.

* New OpenEHR::TerminologyService seam: RM classes that must validate
  codes against a terminology (COMPOSITION.language/category,
  EVENT_CONTEXT.setting, ISM_TRANSITION.current_state/transition) now
  call through it instead of skipping validation entirely. The default
  provider is fully permissive (this gem carries no terminology data -
  that lives in the separate openehr-terminology gem); plug in
  OpenEHR::TerminologyService.provider = my_adapter for real validation.
* DV_AMOUNT gained the spec's valid_percentage(number) class function
  and unary minus (-@, a non-mutating negated copy).
* Identification hardening: UUID, InternetID (RFC 1034 domain form) and
  IsoOID (ISO/IEC 8824 OID form) now validate their value's format
  instead of accepting any non-empty string; ArchetypeID's parsing
  regexes are now fully anchored (previously matched a valid id embedded
  anywhere in a longer garbage string) and no longer truncate the
  specialisation part of domain_concept to a single character (a bug an
  assertion-less test had been silently masking).
* MeasurementService implements is_valid_units_string?/units_equivalent?
  as a minimal UCUM-lite syntactic checker (allowed-character and
  balanced-bracket check, not a full UCUM parser or conversion table -
  documented as such).
* PartyRelationship#source= no longer requires the source PARTY_REF's id
  to equal the relationship's own uid (not a spec invariant - the
  relationship's uid identifies the relationship object itself, not the
  owning party) - BREAKING: a source with a different id is now valid
  instead of raising.
* Factory: fixed TermMappingFactory being defined twice (the second
  definition silently shadowed the first). Added factories for Element,
  ItemTree/ItemList/ItemSingle/ItemTable, History/Event/PointEvent/
  IntervalEvent, the remaining Entry subtypes (Evaluation, Instruction,
  Action, Activity, AdminEntry, InstructionDetails, IsmTransition),
  GenericEntry, common/generic types (PartySelf, PartyRelated,
  Participation, Link, FeederAudit, AuditDetails, Attestation),
  identification types (ObjectRef, LocatableRef, ObjectVersionID,
  HierObjectID, UIDBasedID, AccessGroupRef), and demographic types
  (Person, Organisation, Role, PartyIdentity, Contact, Address,
  Capability, PartyRelationship) - previously only a handful of RM types
  (mostly data types plus Observation/Section/Cluster) could be built
  through Factory.create, so e.g. an archetype-driven build of a CLUSTER
  containing ELEMENTs was impossible. EHR/EHR_ACCESS/EHR_STATUS/
  VERSIONED_* factories are deliberately not included yet: those RM
  classes have their own pre-existing duck-typed #type checks that need
  fixing first (a separate piece of work).

=== 1.4.0 (in progress)
openEHR path navigation: implemented item_at_path, items_at_path,
path_exists?, path_of_item and path_unique? on PATHABLE (previously all
five raised NotImplementedError with no overrides anywhere in the gem).

* New OpenEHR::Path (lib/openehr/path.rb): a standalone parser for the
  openEHR archetype path syntax (e.g.
  /content[at0001]/data[at0002]/events[at0006]/data[at0003]/items[at0004,
  'Systolic']/value), supporting at-code and archetype-id node_id
  predicates and name-disambiguation predicates. Deliberately rejects
  relative paths, "//" wildcards, and numeric index predicates
  (InvalidPathError).
* Pathable gained a `path_attribute` declaration DSL and `path_children`,
  used to implement the five navigation methods generically via a
  child-enumeration protocol rather than per-class path logic.
  Declared across Composition, Section, Entry/CareEntry/AdminEntry/
  Observation/Evaluation/Instruction/Activity/Action/InstructionDetails,
  GenericEntry, History/Event, ItemTree/ItemList/ItemSingle/ItemTable,
  Cluster/Element, EHRStatus, and Folder.
* item_at_path raises the new PathNotUniqueError when a path predicate
  matches more than one sibling (e.g. a shared node_id needing a name
  predicate to disambiguate) - BREAKING: Pathable's five methods no
  longer raise NotImplementedError; any code catching that is affected.
* ItemTree#element_at_path / #has_element_path? now delegate to the real
  path machinery, so nested paths through CLUSTERs resolve correctly
  (previously only a top-level, non-recursive node_id comparison). The
  legacy bare-node-id calling form (e.g. element_at_path('at0002')) still
  works via a deprecated compatibility shim that normalizes it to
  /items[at0002].
* ItemTable#as_hierarchy already fixed in 1.3.1 (see below) to build a
  Cluster from all rows rather than just the first.
* History#events=, Composition#content=, and Cluster#items= now
  auto-wire each child's #parent to the containing object, fixing
  Event#offset (which relies on @parent.origin) for objects built the
  normal way instead of requiring callers to wire parent manually.

=== 1.3.1
Infrastructure: added GitHub Actions CI (Ruby 3.1-3.4), removed the dead
Travis config and RSpec 1 spec.opts, set required_ruby_version >= 3.1,
moved the load-time charset_extract.rb script out of lib/ into a rake
task, updated History.txt/README.

Fixed a pre-existing red baseline (35 failing examples, none introduced
by this release) plus latent runtime bugs found by a full
spec-vs-implementation audit, each driven by a failing spec first:
* OperationalTemplate constructor validation order - template_id and
  description are now validated with their own mandatory checks instead
  of raising on the inherited Archetype#concept= check first; concept
  is derived from archetype_id when not given explicitly.
* OPTParser: missing/blank template_id and uid resolve to nil instead of
  raising; #occurrences and #cardinality return nil instead of raising
  when their XML carries no data at all.
* C_INTEGER allows a fully unconstrained (any_allowed) construction with
  neither range nor list set, per AOM 1.4 (only having both set is a
  contradiction) - BREAKING: CInteger.new with neither range nor list no
  longer raises.
* ISO8601Duration parses multi-digit day counts (e.g. "P10D"); absent
  components stay nil instead of being coerced to 0, so as_string can
  round-trip a partially-specified duration - BREAKING: absent duration
  components now read as nil instead of 0.
* ISO8601Time.valid_iso8601_time? no longer rejects timezone-less times.
* DvOrdered#is_normal? calls Interval#has? (was #has, undefined).
* DvAmount#- no longer mutates its right-hand operand.
* DvCount enforces an Integer magnitude.
* time_specification.rb: fixed the misspelled NotImlementedError
  constant (was a NameError on every call); added a spec file (none
  existed).
* Fixed three unresolved-constant NameErrors masked by cross-spec-file
  namespace pollution: Locatable#concept (DvText), Version#owner_id
  (HierObjectID), Entry#subject_is_self? (PartySelf).
* Element#null_flavor= no longer calls a nonexistent ActiveRecord-style
  Terminology.find; validates against the openEHR null flavours code set
  locally. Added #null_flavour alias.
* DvEncapsulated's charset.lst lookup uses an absolute path instead of a
  cwd-relative one (broke for installed gems).
* DvMultimedia gained is_external?, is_inline?, is_compressed?,
  has_integrity_check?, and a thumbnail attribute; media_type= no longer
  raises NoMethodError when media_type itself is nil.
* VersionedObject#latest_trunk_version now selects the most recently
  committed non-branch version instead of only ever considering
  trunk_version "1" - BREAKING: return value changes when multiple
  non-branch versions exist. #all_versions= now rejects an empty array,
  not just nil.
* ItemTable#element_at_named_cell no longer has its row/column indices
  transposed and off-by-one; #as_hierarchy returns a Cluster of all rows
  instead of just the first row - BREAKING: as_hierarchy's return shape
  changes.
* CPrimitiveObject no longer defines a garbage method literally named
  "any_allowed?," from a stray comma in a %w list.
* CDateTime constructor: fixed :hour_vaildity typo and month_validity
  being fed from :day_validity instead of :month_validity.
* ArchetypeOntology#code_set no longer discards its accumulator each
  iteration (term_codes/constraint_codes now return the union across all
  languages, not just the last one).
* CQuantityItem#precision_unconstrained? no longer raises when precision
  is absent.
* ADL grammar: fixed three crash bugs (misspelled SYM_IS_CONTROLED,
  missing SYM_NE rule for "!=" assertions, a debug-print typo in the
  generic C_DOMAIN_TYPE/C_DV_STATE fallback) and a wrong namespace
  (ConstraintModel::ExprLeaf instead of Assertion::ExprLeaf) that broke
  every arithmetic assertion comparison (=, !=, <, >, <=, >=) whenever
  the leaf was an integer, real, or path constant.
* ObjectVersionID#value= now populates root/extension (root = the
  object id part) so #root, #extension and #has_extension? work.
* LocatableRef.path is optional again, matching the spec's 0..1
  cardinality; #as_uri omits the path segment when absent.
* EVENT_CONTEXT gained the optional health_care_facility attribute.
* VersionedParty now extends VersionedObject instead of Locatable,
  matching VERSIONED_OBJECT<PARTY> - BREAKING: constructor signature
  changes to VersionedObject's (uid/owner_id/time_created/all_versions).
* PartyIdentified's identifiers attribute is now plural (a
  List<DV_IDENTIFIER>, matching spec); #identifier/#identifier= remain
  as deprecated aliases.
