=== 2.4.2 (unreleased)
Version number is a placeholder, finalized at tag time from the actual
diff accumulated since 2.4.1 (per this file's own Release convention).

* RMJSONSerializer now emits the canonical "value" key for ArchetypeID
  and TerminologyID (both OBJECT_ID subtypes) instead of only their
  internal decomposed fields (rm_originator/rm_name/rm_entity/
  concept_name/specialisation/version_id for ArchetypeID; name/
  version_id for TerminologyID) - the same class of gap #32 fixed for
  ObjectVersionID, generalized to these two sibling types. The
  exclusion is scoped to these two classes specifically (not a global

  :@version_id ivars (e.g. any Locatable's #name, or
  RevisionHistoryItem#version_id) are unaffected. Reading back JSON
  persisted by a prior version of this gem (decomposed keys only, no
  "value") is unaffected - Factory already reconstructs both types
  from their individual fields when "value" is absent. (#46, first
  reported as #45)

=== 2.4.1
Diagnostics and correctness release: AQL WHERE-clause alias-collision
errors get a clearer hint, and RMJSONSerializer no longer treats
non-cyclic attribute aliasing as a cycle.

* AQL parser diagnostics: referencing a SELECT alias in a WHERE clause
  (not supported by AQL) used to fail with a bare "expected a
  comparison operator, LIKE or MATCHES, got identifier ..." error. When
  the unexpected identifier matches a known SELECT alias name, the
  error now appends a "note: '<name>' is a SELECT alias; aliases
  cannot be used in WHERE -- repeat the identified path" line. No
  WHERE-clause alias support was added - diagnostics only. (#38)
* Compatibility note: this changes OpenEHR::AQL::ParseError#message's
  text in the one alias-collision case above; every other ParseError
  message is unchanged. An audit of this gem's own specs
  (spec/lib/openehr/aql/) found zero pre-existing assertions matching
  a ParseError#message by full string equality - only type checks,
  regex/substring matches, or #include - so no existing spec needed
  updating. This PR adds the gem's first full-equality ParseError
  message assertion, specifically to pin the *unchanged* (non-alias)
  case. A downstream caller matching this gem's error text by exact
  string equality is the only audience this note is for.
* RMJSONSerializer's cycle guard now only treats an object as "seen"
  while it's actively being recursed into (pushed on entry, popped on
  exit) rather than permanently once first encountered. Two different
  attributes on the same object that alias the same sub-object (e.g.
  OperationalTemplate#template_id=, which sets both template_id and
  archetype_id to the identical object) now both serialize that
  sub-object's real value; previously the second occurrence silently
  serialized as null. Genuine cycles (e.g. PATHABLE's @parent, already
  excluded from traversal separately) are still caught correctly -
  this only narrows what counts as "seen", it does not remove the
  guard. Observable change: any output containing a previously-nulled
  aliased attribute will now contain that attribute's real value
  instead. (#40)

=== 2.4.0
Bug fix release: RMJSONSerializer <-> CompositionFactory.create_from_json
roundtrips now work.

* RMJSONSerializer no longer emits derived-cache instance variables
  that aren't part of canonical openEHR ITS-JSON: DvDate/DvTime/
  DvDateTime's year/month/day/hour/minute/second/fractional_second/
  timezone (all recomputed from `value` on read), and UIDBasedID/
  HierObjectID/ObjectVersionID's root/extension/oid/
  creating_system_id/version_tree_id (also recomputed from `value`).
  Previously, serializing a DvDateTime or a Composition carrying a uid
  (ObjectVersionID/HierObjectID - a common real-world attribute) and
  feeding the result back into create_from_json raised NameError:
  uninitialized constant ...Factory::TimezoneFactory (or UidFactory) -
  no such Factory class existed for either derived cache. The gem's
  own fixture had no `uid` field, so the UID-family case had never
  been exercised until this investigation found it.
* Factory.params now tolerates an unrecognized `_type` on a Hash
  value instead of raising: a _type matching one of the
  now-excluded derived caches above (TIMEZONE, UID, VERSION_TREE_ID)
  is silently ignored - this is what makes JSON persisted by a prior
  version of this gem (which still contains those keys) readable
  again. Any other, genuinely unrecognized `_type` is also ignored,
  but with a Kernel#warn naming it, so a real authoring mistake
  (e.g. a typo'd _type) doesn't fail silently.
* Also includes one internal representation change to an RM class:
  ObjectVersionID#value= (lib/openehr/rm/support/identification.rb)
  never stored @value at all - unlike its UIDBasedID parent, its
  canonical `value` existed only as a getter recomputed from the
  now-excluded oid/creating_system_id/version_tree_id. This is part
  of why the roundtrip broke: a class that keeps no canonical
  attribute in ivar form has nothing left for the serializer to see
  once the derived caches around it are excluded. Fixed by storing
  @value alongside those, matching UIDBasedID's own pattern; the
  `value` getter itself is unchanged. Net effect on ObjectVersionID's
  serialized JSON specifically: `oid`, `creating_system_id`,
  `version_tree_id`, `root`, and `extension` disappear (as with the
  other derived caches above), and `value` newly appears (it was
  never present in this class's output before, unlike HierObjectID's,
  which already had it via inheritance from UIDBasedID/ObjectID).

=== 2.3.2
Hardening release: already-safe OPT/archetype XML parsing is now explicit
and regression-pinned instead of relying on Nokogiri's implicit defaults.

* OPTParser and XMLArchetypeParser now use an explicit
  OpenEHR::Parser::Base::SAFE_PARSE_OPTIONS (RECOVER | NONET | BIG_LINES).
  The currently resolved Nokogiri already used those same safe defaults,
  with NOENT and DTDLOAD disabled, so this does not fix an exploitable
  vulnerability or change parsing behavior. It makes the existing safety
  properties independent of future changes to Nokogiri's default option
  constant and pins them with local-file entity regression tests. Parser
  callers cannot override these options.

* Independently, file handles opened by OPTParser and XMLArchetypeParser
  are now closed deterministically with block-form File.open instead of
  being left to garbage-collector finalization.

=== 2.3.1
Bug fix release: OPT parsing no longer crashes on C_CODE_REFERENCE
or other unknown constraint child types.

* OPTParser (and XMLArchetypeParser, which shares the same constraint
  readers) raised NoMethodError on templates containing
  <children xsi:type="C_CODE_REFERENCE"> - emitted by tools such as
  Archetype Designer when a DV_CODED_TEXT defining_code is bound to an
  external terminology reference set. Such children now parse into the
  new ...Text::CCodeReference (a CCodePhrase subclass, mirroring
  Template.xsd's C_CODE_REFERENCE extension) carrying referenceSetUri
  as #reference_set_uri. valid_value?/any_allowed? do not expand the
  reference set (no terminology service is wired), so an otherwise
  unconstrained C_CODE_REFERENCE validates permissively.
* Unknown <children> xsi:type values no longer abort the parse: an
  unrecognized constraint type falls back to plain C_COMPLEX_OBJECT
  reading with a Kernel#warn to stderr naming the type and node path.
  The fallback keeps the C_OBJECT core but drops the unknown type's
  specific constraint payload, so validation of that node becomes more
  permissive than the template author intended - the warning makes
  this visible. There was no prior verified, type-specific contract
  here to preserve: OPTParser and XMLArchetypeParser share the exact
  same dispatch code, but only XMLArchetypeParser wrapped the
  resulting NoMethodError into a ParseError, and only as an incidental
  side effect of a generic top-level `rescue StandardError` around
  its whole parse (confirmed by inspecting the wrapped error - the
  ParseError's message was, character for character, the stringified
  NoMethodError). OPTParser had no such rescue and raised the same
  NoMethodError raw. The two parsers already disagreed on the same
  bug; this release makes them agree. A structurally invalid unknown
  node (missing occurrences) still raises - via ParseError on the
  XMLArchetypeParser path, raw on the OPTParser path, matching each
  path's pre-existing general error-handling behavior (tracked as a
  separate backlog item, not changed by this release). C_DV_STATE
  still raises NotImplementedError as before.
* Not included: XMLSerializer does not yet emit C_CODE_REFERENCE -
  serializing a parsed CCodeReference degrades it to an unconstrained
  C_CODE_PHRASE (referenceSetUri dropped). Round-trip support is
  deferred to the serializer work item.
* Development: wired rubocop-rspec into the existing rubocop setup,
  with a generated .rubocop_todo.yml excluding the 7720 pre-existing
  RSpec-style offenses so `bundle exec rubocop` stays green while the
  todo shrinks gradually. Development/test group only - no runtime or
  gemspec impact.

=== 2.3.0
Feature and bug fix release: AQL execution catches up to the parser
on 4 previously-ExecutionError constructs, and a Factory.create entry
point that's been broken since 2.0.0 is fixed.

* AQL: WHERE ... LIKE, WHERE ... MATCHES {...} (literal value list),
  CONTAINS class-expression node/standard predicates ("CONTAINS
  ELEMENT e2[at0004]", "...[name/value='Systolic']", and their AND/OR
  combinations), and a SELECT mixing a plain column with an aggregate
  were all already parsed correctly but raised ExecutionError the
  moment the engine tried to run them - all four now execute:
  - LIKE follows the AQL spec's glob syntax (? = one char, * =
    zero-or-more, whole-string anchored, no wildcard behaves like =) -
    not SQL's %/_, which some real-world queries use by habit but
    isn't what the spec defines.
  - MATCHES against a literal value list is a pure in-memory
    membership check. A URI or TERMINOLOGY(...) operand names an
    external terminology-server value-set expansion this engine has
    no service wired for (OpenEHR::TerminologyService only validates a
    single known code, it doesn't expand a value set) - those still
    raise, now with a clear explanation instead of a generic "yet".
  - CONTAINS node/standard predicates reuse the same
    PathEvaluator/PredicateEvaluator machinery the EHR-root predicate
    already used (2.2.0), generalized to any CONTAINS-matched
    candidate instead of just the EHR record.
  - A mixed aggregate/non-aggregate SELECT implicitly groups by every
    non-aggregate column's value (the standard SQL reading when no
    explicit GROUP BY is given) - zero surviving rows therefore
    produces zero groups, unlike the all-aggregate case's single row
    of aggregate defaults.
* Fixed: OpenEHR::RM::Factory.create('COMPOSITION', ...) raised
  NoMethodError - every other *Factory subclass overrides
  self.create(param); CompositionFactory only defined
  create_from_json. Reported repeatedly by openehr-rails across
  2.0.0-2.2.0 (create_from_json worked around it, so not urgent for
  them).

=== 2.2.0
Bug fix and feature release: AQL/RM 1.1.0 spec-compliance fixes,
ADL/XML serializer round-trip completeness, and a new XML archetype
parser.

* Fixed two AQL execution bugs that returned silently wrong results
  (no error, just the wrong rows):
  - `FROM EHR e [ehr_id/value=$ehr_id]`-style EHR-root predicates -
    the idiom used by roughly a third of the official AQL examples to
    scope a query to one patient - were parsed but never evaluated,
    so every query matched every EHR regardless of the predicate.
  - `SELECT TOP n` was parsed but never applied, so queries returned
    every row instead of just the top n.
* RM 1.1.0/1.0.4 relaxed several attributes from mandatory to optional
  that this gem still enforced as mandatory, rejecting valid RM 1.1.0
  data: DV_IDENTIFIER.issuer/assigner/type, PARTICIPATION.mode,
  ISM_TRANSITION.transition, EHR.contributions/EHR.compositions.
* Added the two RM 1.1.0 attributes this gem was missing entirely:
  DV_MULTIMEDIA.size (falls back to the inherited value-based size
  when not given explicitly, so existing callers are unaffected) and
  ELEMENT.null_reason (requires null_flavor to already be set).
* DV_AMOUNT/DV_TEMPORAL arithmetic: DvAmount#+/-/-@ read and wrote the
  @magnitude ivar directly, which silently produced wrong results for
  DvProportion (its magnitude is derived from numerator/denominator,
  never ivar-backed - 2/3 + 1/3 returned 2/3 unchanged, no error).
  DvAmount now builds results through an overridable hook, with a new
  `multiply`/`*`; DvProportion overrides +/-/-@/multiply at the
  numerator/denominator level instead. DV_DURATION gained +/-/multiply,
  and DV_DATE/DV_TIME/DV_DATE_TIME gained #add/#subtract against a
  DV_DURATION (month-end clamping, leap years, day/timezone
  wraparound) - previously calling .add/.subtract on any of these
  raised ArgumentError immediately, so only #diff worked at all.
* ADLSerializer: added C_DV_QUANTITY support (a very common real-world
  constraint type that previously made any archetype using it
  unserializable), plus the archetype-level sections it was silently
  dropping - uid, specialise, language/translations, an invariant
  section, and the ontology's primary_language/constraint_definitions/
  constraint_bindings.
* XMLSerializer rewritten to the canonical openEHR ITS-XML shape.
  Concretely, its own output could not be read back by this gem's own
  OPTParser: `<occurrence>` (singular) instead of `<occurrences>`, no
  xsi:type on `<attributes>` at all (OPTParser can't dispatch attribute
  reading without it), flat text where the schema nests, and ASSERTION
  as flat text even though Assertion#expression= is non-nil-mandatory.
  Also adds C_DV_QUANTITY/C_DV_SCALE support and fixes the same
  ordinal symbol.code_string bug ADLSerializer had.
* New: XMLArchetypeParser, closing the "XML archetype parser (in
  progress)" gap the README had documented. Reads the canonical shape
  XMLSerializer now emits, sharing constraint-tree node builders with
  OPTParser (both extracted into 3 shared modules under
  lib/openehr/parser/). Verified end-to-end by round-tripping real
  archetypes through ADLParser -> XMLSerializer -> XMLArchetypeParser
  and comparing against the ADLParser-built original.
* Along the way, found and fixed two more pre-existing bugs shared
  with OPTParser, neither previously triggered by its existing .opt
  fixtures: sibling C_COMPLEX_OBJECT/ARCHETYPE_SLOT nodes under one
  C_MULTIPLE_ATTRIBUTE corrupted each other's paths (a shared mutable
  Node object leaked path state between siblings), and
  ARCHETYPE_SLOT's own node_id was never folded into its path.
* Ruby support narrowed to 3.3, 3.4, and 4.0 (3.2 dropped, EOL),
  following this gem's existing "Ruby core's currently-supported
  versions only" policy.

=== 2.1.0
New feature and maintenance release.

* Implemented DV_TIME_SPECIFICATION / DV_GENERAL_TIME_SPECIFICATION /
  DV_PERIODIC_TIME_SPECIFICATION (openEHR's HL7-GTS-backed time
  specification classes). DvPeriodicTimeSpecification was previously
  uninstantiable (its constructor called a method that only existed,
  as an empty no-op, on the sibling class), and DvGeneralTimeSpecification's
  formalism check called a nonexistent method - both were dead code
  left unimplemented since the original author couldn't obtain HL7's
  spec text at the time. HL7's spec is public now: these classes parse
  the single-literal PIVL ("[phase_low(;phase_high)?]/(period)@ALIGN? IST?",
  e.g. "[200004181100;200004181110]/(7d)@DW IST") and EIVL
  ("EVENT([+-]offset)?", e.g. "ACM+10min") forms and expose the
  openEHR-mandated derived accessors (period, calendar_alignment,
  event_alignment, institution_specified); composed/set-algebra GTS
  expressions are out of scope and raise a clear ArgumentError.
  **Breaking change**: DvTimeSpecification and its subclasses moved
  from a positional `new(value)` constructor to the hash-based
  `new(value: ...)` pattern every other RM class uses (also required
  for Factory registration - all 3 classes are now Factory-creatable),
  and DvTimeSpecification#value now requires a DV_PARSABLE-shaped
  object rather than accepting anything non-nil.
* ADLSerializer and XMLSerializer made frozen-string-literal safe:
  the handful of methods that mutated a bare string literal in place
  now seed from an explicit unfrozen copy, and both files (plus
  serializer/base.rb) carry `# frozen_string_literal: true` so any
  future regression fails loudly instead of silently warning.
* RuboCop offense backlog burned down from 158 to 0, and the CI
  rubocop job is now blocking (previously `|| true`). Along the way:
  fixed 2 real test bugs (6 float-comparison assertions that never
  actually ran because they were missing `expect(...)`; 2 vacuous
  placeholder tests), a handful of dead/redundant methods, and moved
  development dependencies from the gemspec into the Gemfile.

Bug fix and maintenance release.

* Fixed: OpenEHR::RM::Factory.params/convert_value raised a confusing

  could silently resolve to a version whose add_filter/add_group are

* Miscellaneous warning cleanup: fixed a circular require, a duplicate
  ADL grammar rule, a handful of ambiguous-operator and redundant

=== 2.0.1
Bug fix release.

* Fixed: OpenEHR::RM::Factory.params (and therefore
  CompositionFactory.create_from_json) only recursively converted
  Hash-valued attributes into RM objects, never Array-valued ones.
  Every RM attribute with openEHR multiplicity 0..*/1..* -
  COMPOSITION.content, HISTORY.events, ITEM_TREE.items, CLUSTER.items,
  and so on - is a JSON array of typed sub-objects, so any composition
  rebuilt via create_from_json (the path this gem's own README
  recommends for supplying data to the AQL engine) silently kept raw
  Hashes nested inside it instead of real RM objects. This never
  raised an exception: it just made AQL CONTAINS queries against that
  data return zero rows, since OpenEHR::AQL::Dataset only checks that
  top-level compositions are Pathable, and the CONTAINS subtree walk
  quietly skips anything that isn't. Reported by openehr-rails after
  upgrading to 2.0.0 and following this exact integration pattern.
  Array values now recurse the same way Hash values already did,
  cascading through arbitrarily deep nesting; non-Hash array elements
  (e.g. DV_PARAGRAPH's plain-string items) are left untouched.
* Local development environment bumped to Ruby 4.0.6; CI gained a
  '4.0' matrix entry alongside the existing 3.1-3.4 (the declared
  minimum-supported floor, >= 3.1, is unchanged).

=== 2.0.0
AQL (Archetype Query Language): a hand-written lexer/parser plus an
in-memory execution engine, evaluating queries directly against RM
object graphs. This is the headline feature behind the major version
bump, together with the scope declaration it comes with: AQL here
queries in-memory data only, never a persistent store or search index.

Parser (lib/openehr/aql/lexer.rb, parser.rb, model/*):
* Hand-written Lexer + recursive-descent Parser, not a parser
  generator - method names mirror the official AqlLexer.g4/AqlParser.g4
  rule names for traceability against the reference grammar, and error
  messages carry a 1-based line/column ("expected FROM, got WHERE
  (line 2, column 8)").
* Full SELECT/FROM/WHERE/ORDER BY/LIMIT/OFFSET coverage: DISTINCT and
  the deprecated TOP N form; EHR/CONTAINS class expressions nested to
  any depth, with archetype-id and at-code/id-code node predicates
  (including their AND/OR combination and comma-separated name/param
  suffix); SELECT paths with node predicates and AS aliases; WHERE
  comparisons/AND/OR/NOT/parens/EXISTS/LIKE/MATCHES (literal value
  list, a bare URI, or a TERMINOLOGY(...) call); boolean containment
  grouping and NOT CONTAINS; aggregate functions (COUNT/MIN/MAX/SUM/
  AVG) and generic function calls.
* Validated against all 19 example queries in the official AQL
  specification (specifications.openehr.org), and against 33 real-world
  queries sourced from EHRbase's own AQL parser test suite and a
  regression fixture (both Apache License 2.0) - production AQL
  exercises considerably more of the grammar than the spec's own
  textbook examples do, and closed several real parser gaps this way
  (a predicate directly on a SELECT variable, nodePredicate's AND/OR
  combination and comma-suffix, an objectPath as a predicate's
  comparison operand).
* Deliberately unimplemented (documented, not silently wrong): TERM_CODE
  literals, CONTAINED_REGEX, dedicated DATE/TIME/DATETIME literal
  tokens (quoted values are treated as generic strings), and
  VERSION/LATEST_VERSION/ALL_VERSIONS version-aware containment
  (out of scope by design - see below).

Execution engine (lib/openehr/aql/engine.rb, engine/*, result_set.rb):
* OpenEHR::AQL::Dataset is the engine's only input boundary, and the
  whole of its independence from any particular web framework or O/R
  mapper: it depends on nothing but Ruby's Enumerable/#each protocol
  and this gem's own RM classes - no ActiveRecord, no Rails, no
  Sequel, anywhere under lib/openehr/aql/. Dataset.new(ehrs:) accepts
  a Hash, a duck-typed record object, or a full OpenEHR::RM::EHR::EHR
  (unwrapped via VersionedObject#latest_version); Dataset.of_compositions
  and Dataset.wrap cover quick, non-database scripts. Construction
  never iterates its source, so a lazily-produced Enumerable (e.g. an
  ActiveRecord find_each.lazy chain, entirely outside this gem) stays
  lazy all the way through execute. Every composition is checked
  against is_a?(Pathable) at normalization time, raising DatasetError
  (naming the offending class/index) otherwise.
* The pipeline runs CONTAINS -> WHERE -> ORDER BY -> SELECT ->
  DISTINCT -> LIMIT/OFFSET. CONTAINS resolution searches a matched
  Locatable's entire subtree at any depth (not just direct children),
  correctly implementing AND-grouped (cross product), OR-grouped
  (union) and NOT CONTAINS (subtree-absence) sibling branches. SELECT
  paths walk PATHABLE#items_at_path for declared path_attributes and
  fall through to a small, explicit whitelist of public_send hops for
  RM metadata/non-Pathable terminals outside that DSL (never an
  arbitrary send driven by query text) - a path matching nothing
  resolves to nil (AQL's path-absent-means-null semantics), not an
  error. WHERE comparisons, AND/OR/NOT, EXISTS and $parameter binding
  are fully wired; a SELECT clause made entirely of aggregate columns
  collapses the whole result into one summary row.
* ResultSet#to_json follows the openEHR REST Query API's result-set
  shape (columns/rows), reusing the existing RMJSONSerializer for any
  RM object row values.
* Not yet wired into WHERE execution (parsed, not evaluated): LIKE,
  MATCHES, and function-call operands. Mixing aggregate and
  non-aggregate SELECT columns raises a clear error rather than
  guessing at SQL's GROUP BY-less semantics.
* See README.rdoc's new "Querying with AQL" / "Supplying data to AQL"
  sections for the public API and the Dataset contract in full,
  including a worked (outside-this-gem) Rails+ActiveRecord adapter
  sketch alongside a plain-script example.

This release also folds in 1.4.0-1.8.0 below, which had accumulated
since 1.3.1 without being cut as separate gem releases.

=== 1.8.0
RM 1.1.0 / BASE 1.2.0 deltas layered onto the 1.0.2 baseline. See the new
"RM 1.0.2 vs RM 1.1.0 semantics" section in README.rdoc for the full
list and which RM version each item belongs to.

* New DvScale (DataTypes::Quantity) and its AOM constraint CDvScale
  (OpenEHRProfile::DataTypes::Quantity), plus a DvScaleFactory and an
  OPTParser#c_dv_scale handler - RM 1.1.0's SPECRM-19, a DV_ORDINAL
  sibling for scales/scores whose points are Real-valued rather than
  Integer-valued (e.g. the Borg CR10 breathlessness scale, which
  includes 0.5).
* DvQuantity gained units_system and units_display_name (SPECRM-65,
  both optional): units is UCUM by default, units_system names another
  units system when it isn't, and units_display_name gives a
  displayable form when the units code itself isn't one (UCUM 'Cel' vs
  '°C'). is_strictly_comparable_to? now also requires units_system to
  match, not just units.
* CodePhrase gained an optional preferred_term (String), for
  integration mappings that need both a non-preferred actual term and
  a preferred term.
* DvParagraph now emits a deprecation warning on construction (it's
  been deprecated since RM 1.0.4 in favour of DvText/DvCodedText with
  markdown or newlines) - it remains legal and fully functional, this
  only warns, since it's still needed for legacy data.
* Negative ISO8601 durations (e.g. "-P10D", meaning "10 days before an
  unstated origin point" - used for e.g. a premature newborn's adjusted
  age) are now consistently supported (SPECRM-96): ISO8601Duration and
  DvDuration both gained negative?/negative=, to_seconds/magnitude and
  as_string are sign-aware, and DvDuration gained unary -@ (DV_AMOUNT's
  "negative" operation), returning a new DvDuration with the sign
  flipped. Component setters (years=, days=, ...) still reject negative
  magnitudes - the sign applies to the duration as a whole.
* EHR gained folders (SPECRM-55, List<OBJECT_REF>, optional): when set,
  directory is kept pointing at folders.item(1) (the Directory_in_folders
  invariant), for backward compatibility with pre-1.1.0 systems that
  only had directory.
* FOLDER gained details (optional ITEM_STRUCTURE, archetypable
  meta-data), and FEEDER_AUDIT_DETAILS gained other_details (SPECRM-74,
  optional ITEM_STRUCTURE, custom meta-data).
* ACTIVITY.timing is no longer mandatory - RM 1.1.0 made it optional
  (it may be omitted when timing is instead represented structurally in
  description, or is unavailable, e.g. imported legacy data).
* IsmTransition gained an optional reason (List<DV_TEXT> - one or more
  reasons for a careflow step, e.g. useful in medication management).
* COMPOSITION.category accepting "episodic" (SPECRM-89) needed no code
  change: category validation already goes through the pluggable
  OpenEHR::TerminologyService seam (1.5.0), which is terminology-content
  agnostic by design.

=== 1.7.0
Serializers: ADLSerializer can now emit a full cADL definition section
instead of hanging.

* ADLSerializer#definition previously infinite-looped on any archetype
  whose definition had attributes (`while attributes` never advanced -
  every real archetype beyond the most trivial `matches {*}` case would
  hang forever). Replaced with a recursive cADL emitter covering
  C_COMPLEX_OBJECT, C_SINGLE_ATTRIBUTE/C_MULTIPLE_ATTRIBUTE (with
  existence/cardinality, only emitted when non-default), all eight
  C_PRIMITIVE types (boolean/integer/real/string/date/time/date_time/
  duration - pattern, list and range forms, plus assumed_value),
  C_CODE_PHRASE, C_DV_ORDINAL, CONSTRAINT_REF and ARCHETYPE_SLOT
  (rendering its include/exclude assertions verbatim via their
  string_expression). C_DV_QUANTITY (dADL block syntax) and C_DV_STATE
  are not yet supported and raise ArgumentError rather than emit
  incorrect output. Verified via round-trip tests (parse -> serialize ->
  re-parse -> same archetype_id/physical_paths) against real archetypes,
  including ones using slots and ADL 1.4's short at0.N specialisation
  node-id form.
* Fixed a real, previously-undiscovered bug hit while building the
  above: the ADL grammar represented a bare "matches {*}" (any_allowed)
  C_COMPLEX_OBJECT by synthesizing a fake CAttribute named "ANY" into
  its attributes array, instead of leaving attributes empty - so
  CComplexObject#any_allowed? (and therefore #valid_value? and
  #default_value, added in 1.6.0) incorrectly returned false for every
  `matches {*}` node parsed from real ADL, which is an extremely common
  pattern (e.g. plain "DV_TEXT matches {*}"). Fixed at the source: the
  grammar now leaves attributes unset for this case.
* Fixed two more copy/paste bugs while rewriting the serializers:
  ADLSerializer#description checked item.other_details but then
  iterated item.original_resource_uri; both ADLSerializer#ontology and
  XMLSerializer#ontology assumed each language's term definitions were
  an Array of ArchetypeTerm and called item.code, but
  ArchetypeOntology#term_definitions is actually a Hash of {code =>
  ArchetypeTerm} (per term_definition/term_codes' own lookups) - so
  both crashed with NoMethodError on any archetype ontology with more
  than one term, which the two serializers' own tests never exercised
  since their sample fixture only used a single term either way.
* XMLSerializer#definition rewritten the same way, recursing into the
  full constraint tree (previously only rm_type_name/occurrence/node_id
  for the root, nothing else) with an xsi:type discriminator on each
  <children> element for the concrete AOM node class.
* Both ADLSerializer#ontology and XMLSerializer#ontology now also emit
  languages_available, terminologies_available and term_bindings
  (constraint_definitions/constraint_bindings remain unhandled - no real
  archetype in this gem's corpus exercises them, so there was nothing to
  verify serialization against; documented gap for future work).
* New OpenEHR::Serializer::RMJSONSerializer: canonical JSON for an RM
  instance graph via a generic reflection walker (every instance
  variable except PATHABLE's @parent back-reference, "_type" from
  OpenEHR::RM.type_name_of), rather than a hand-written serializer per
  RM class. Since the walker has no RM-specific logic, it also
  serializes AOM constraint trees (CComplexObject, CAttribute, ...)
  correctly as-is; exposed under that alias as
  OpenEHR::Serializer::JSONSerializer rather than duplicating it.
* OPTParser gained the C_TIME and ARCHETYPE_INTERNAL_REF (use_node)
  handlers it was missing - either constraint in a real .opt previously
  crashed parsing with a bare NoMethodError, since both are dispatched
  dynamically by XML type name. C_DV_STATE (state machine) constraints
  now raise a clear, documented NotImplementedError instead of that same
  crash; no .opt fixture in this gem's corpus uses one, so its actual
  XML shape is unverified and guessing at it risked silently building
  the wrong StateMachine.
* Fixed OPTParser#c_dv_ordinal building its list as bare Integers,
  discarding each option's coded symbol entirely - CDvOrdinal#valid_value?
  (1.6.0) needs both the value and the symbol to match, so every
  OPT-sourced C_DV_ORDINAL constraint failed to validate any value
  against it. Also fixed CDvOrdinal#valid_value? itself: it called
  symbol.code_string directly, but DV_ORDINAL.symbol is spec'd as
  DV_CODED_TEXT, which only exposes a code via defining_code.code_string
  - the bug was masked by every existing test using a double that
    stubbed code_string directly rather than a real DvCodedText.
* Fixed OPTParser#c_duration silently dropping range constraints
  (deliberately, per a since-removed comment - ISO8601 duration bounds
  like PT24H aren't plain numbers, so the existing numeric-Interval
  helper didn't apply). Range bounds are now wrapped as DV_DURATION,
  matching what CDuration#valid_value? already expects.
* Fixed OperationalTemplate#ontology using a fabricated single-term
  placeholder ("at0000: Template") instead of the real ontology data,
  which was already being captured correctly per-archetype in
  component_terminologies during parsing - the root archetype's own
  entry was simply never looked up and used.
* OPTSerializer#header/#context/#content implemented (previously one
  empty method and two bodyless pending specs). The previous #header
  spec (removed) expected a simulated RM COMPOSITION instance -
  name/archetype_details/territory/composer - that didn't match its own
  test fixture at all (it even named a different archetype_id and
  template_id) and appears to have been aspirational rather than
  ever-passing; an operational template carries constraints, not
  instance data, so #header is template-level metadata (concept, root
  archetype_id, template_id, language) instead. #context/#content
  serialize the root archetype's context/content constraint subtrees as
  JSON via the new JSONSerializer.
* Removed dead code: the never-required lib/openehr/writer.rb, the
  never-required lib/openehr/parser/validator.rb (superseded by
  ArchetypeValidator, 1.6.0) and lib/openehr/parser/xml_parser.rb (a
  typo'd XMLPaser stub, commented out and unused - a real XML archetype
  parser is future work), and the top-level Publisher/Writer classes in
  serializer.rb (referenced by nothing). serializer.rb is now split into
  serializer/{base,adl_serializer,xml_serializer,opt_serializer}.rb.

=== 1.6.0
Archetype Model validation: constraint nodes can now check values and
their own specialisation conformance instead of raising
NotImplementedError or performing no real check at all.

* All eight C_PRIMITIVE subtypes (CBoolean, CInteger, CReal, CString,
  CDate, CTime, CDateTime, CDuration) implement valid_value?, honouring
  range/list/pattern constraints and, for the date/time family, each
  field's ValidityKind (MANDATORY/OPTIONAL/DISALLOWED). CDate/CTime/
  CDateTime#valid_value? accept either an RM DV_DATE/DV_TIME/DV_DATE_TIME
  or a plain ISO8601 string. CInteger and CString's consistency checks no
  longer reject a fully unconstrained node (range/list/pattern all nil);
  previously only CInteger's, and not CString's, allowed this -
  BREAKING: CString.new with all three nil now succeeds instead of
  raising.
* Fixed CDuration#initialize silently discarding the
  years_allowed/months_allowed/weeks_allowed/days_allowed/hours_allowed/
  minutes_allowed/seconds_allowed/fractional_seconds_allowed keyword
  arguments - they were declared as attr_accessor but never read from
  args, so e.g. CDuration.new(:weeks_allowed => false) had no effect.
* New Interval#subset_of?(other): true when every value in self is also
  in other, accounting for unbounded ends and boundary inclusivity. Used
  to implement real specialisation conformance checks.
* CObject#node_conforms_to?(other), CAttribute#node_conforms_to?(other)
  and CMultipleAttribute#node_conforms_to?(other) now perform the actual
  AOM conformance rules instead of inheriting ArchetypeConstraint's
  generic path-prefix check: node_id specialisation (at0001.1 conforms to
  at0001), rm_type_name equality (RM subtype tolerance is deferred until
  the RM type-name helper lands), and occurrences/existence/cardinality
  narrowing (via Interval#subset_of?, with a nil/unconstrained side
  treated as "matches anything" on the parent and "does not narrow
  anything" on the child).
* New OpenEHR::RM.class_for(type_name) / type_name_of(class_or_instance) /
  subtype_of?(class_or_instance, type_name) (lib/openehr/rm/type_name.rb):
  looks up the RM class for a spec type name (or vice versa) and checks
  RM inheritance, by walking the OpenEHR::RM module tree once and
  memoizing a name -> class registry. Accepts UPPER_SNAKE, CamelCase or
  lower_snake input, since rm_type_name is stored in different casings in
  different places in this codebase (the ADL/OPT parsers always produce
  UPPER_SNAKE; some CDomainType constructors hardcode CamelCase).
* CCodePhrase, CDvOrdinal, CDvQuantity (+ its CQuantityItem#matches?) and
  CDvState all gained valid_value?, checking a CODE_PHRASE against
  terminology_id/code_list, a DV_ORDINAL against the value/symbol list,
  a DV_QUANTITY against the per-unit magnitude/precision ranges, and a
  DV_STATE's coded value plus is_terminal? against the constraint's
  StateMachine, respectively.
* CComplexObject#valid_value?(rm_instance) is now a real recursive
  validator instead of raising NotImplementedError: rm_type_name
  conformance (RM subtypes accepted, via OpenEHR::RM.subtype_of?),
  archetype_node_id matching when this node specifies one,
  attribute-by-attribute existence checking, CMultipleAttribute
  cardinality plus per-child-alternative occurrences counting, and
  recursion into each matched attribute value. ArchetypeSlot,
  ArchetypeInternalRef and ConstraintRef children are accepted
  permissively for now (v1 does not resolve slot-fillers or internal
  references - documented limitation).
* CComplexObject#default_value builds the minimal RM instance satisfying
  a node's mandatory constraints (existence lower >= 1 attributes only,
  each attribute's first child alternative's own default_value,
  CMultipleAttribute getting cardinality.interval.lower copies) via
  OpenEHR::RM.class_for; returns nil (rather than raising) whenever a
  mandatory field has no derivable default, since no minimal instance can
  be built in that case.
* The ADL parser now retains the parent archetype id from a specialise
  header instead of discarding it - Archetype#parent_archetype_id is
  populated for specialised archetypes (previously always nil regardless
  of the source ADL).
* Archetype's nine structural-validity methods (physical_paths,
  logical_paths, specialisation_depth, is_specialised?, node_ids_valid?,
  constraint_references_valid?, internal_references_valid?,
  previous_version, is_valid?) all had empty bodies (returning nil
  unconditionally) and now have real implementations: physical_paths/
  logical_paths walk the definition tree (the latter substituting each
  at/ac/id-code predicate with its ontology term text); node_ids_valid?
  checks every node_id is syntactically well-formed and defined in the
  ontology; constraint_references_valid?/internal_references_valid? check
  ConstraintRef/ArchetypeInternalRef targets resolve; is_specialised?/
  specialisation_depth use the newly-retained parent_archetype_id and the
  ontology's own specialisation_depth (falling back to the archetype_id's
  domain_concept suffix); is_valid? composes the three structural checks.
  previous_version stays nil - this gem does not parse ADL revision
  history. The typo'd node_ids_vaild? is kept as a deprecated alias.
* New OpenEHR::Parser::ArchetypeValidator, wiring up the VARID..VDFPT
  archetype-validity rules (exception.rb's Validation error classes were
  defined but never required or used by anything). #errors returns every
  violated rule, #valid? and #validate! (raising the first violation) are
  built on top. #validate_instance(rm_root) separately checks an RM
  instance against the archetype's definition, returning a path-annotated
  InstanceNonConformant (path resolved via the target's own
  path_of_item - the PATHABLE navigation method from 1.4.0) when it does
  not conform. ADLParser#parse gained a validate: keyword (default false,
  preserving existing behaviour) to opt into raising via the validator
  after parsing.
* CComplexObject#find_violation(value): a diagnostic counterpart to
  valid_value? used by ArchetypeValidator#validate_instance, returning
  the first [failing_constraint_node, failing_rm_value] pair found
  instead of a bare boolean.
* The ADL parser now retains the invariant section's assertions
  (previously parsed and then discarded) as Archetype#invariants, an
  array of real Assertion objects (already built by the existing
  assertion/boolean_expression grammar rules - only the archetype-level
  wiring was missing).
* Fixed two further ADL grammar bugs found while exercising the above:
  a tagged invariant/assertion's tag (e.g. "inv1:" in "inv1:1>0") crashed
  with NoMethodError instead of being captured, from calling .value on a
  plain (label-less) sequence node two levels removed from the actual
  identifier; and any_identifier's lowercase-identifier alternative
  crashed with "uninitialized constant V_ATTRIBUTE_IDENTIFIER" because
  Ruby parses a bare ALL-CAPS rule-name reference as a constant, not a
  method call - both are fixed with explicit lower-case labels.
* Fixed OpenEHR::Path::AT_CODE requiring 4+ digits before an optional
  specialisation suffix (at\d{4,}(\.\d+)*) - real ADL 1.4 archetypes use
  a short at0.N form (e.g. at0.2) for nodes newly introduced by a
  specialisation, which the stricter pattern rejected as an invalid path.

=== 1.5.0
RM 1.0.2 behavioral completeness and Factory coverage.

* New OpenEHR::TerminologyService seam: RM classes that must validate
  codes against a terminology (COMPOSITION.language/category,
  EVENT_CONTEXT.setting, ISM_TRANSITION.current_state/transition) now
  call through it instead of skipping validation entirely. The default
  provider is fully permissive (this gem carries no terminology data -
  that lives in the separate openehr-terminology gem); plug in
  OpenEHR::TerminologyService.provider = my_adapter for real validation.
* DV_AMOUNT gained the spec's valid_percentage(number) class function
  and unary minus (-@, a non-mutating negated copy).
* Identification hardening: UUID, InternetID (RFC 1034 domain form) and
  IsoOID (ISO/IEC 8824 OID form) now validate their value's format
  instead of accepting any non-empty string; ArchetypeID's parsing
  regexes are now fully anchored (previously matched a valid id embedded
  anywhere in a longer garbage string) and no longer truncate the
  specialisation part of domain_concept to a single character (a bug an
  assertion-less test had been silently masking).
* MeasurementService implements is_valid_units_string?/units_equivalent?
  as a minimal UCUM-lite syntactic checker (allowed-character and
  balanced-bracket check, not a full UCUM parser or conversion table -
  documented as such).
* PartyRelationship#source= no longer requires the source PARTY_REF's id
  to equal the relationship's own uid (not a spec invariant - the
  relationship's uid identifies the relationship object itself, not the
  owning party) - BREAKING: a source with a different id is now valid
  instead of raising.
* Factory: fixed TermMappingFactory being defined twice (the second
  definition silently shadowed the first). Added factories for Element,
  ItemTree/ItemList/ItemSingle/ItemTable, History/Event/PointEvent/
  IntervalEvent, the remaining Entry subtypes (Evaluation, Instruction,
  Action, Activity, AdminEntry, InstructionDetails, IsmTransition),
  GenericEntry, common/generic types (PartySelf, PartyRelated,
  Participation, Link, FeederAudit, AuditDetails, Attestation),
  identification types (ObjectRef, LocatableRef, ObjectVersionID,
  HierObjectID, UIDBasedID, AccessGroupRef), and demographic types
  (Person, Organisation, Role, PartyIdentity, Contact, Address,
  Capability, PartyRelationship) - previously only a handful of RM types
  (mostly data types plus Observation/Section/Cluster) could be built
  through Factory.create, so e.g. an archetype-driven build of a CLUSTER
  containing ELEMENTs was impossible. EHR/EHR_ACCESS/EHR_STATUS/
  VERSIONED_* factories are deliberately not included yet: those RM
  classes have their own pre-existing duck-typed #type checks that need
  fixing first (a separate piece of work).

=== 1.4.0
openEHR path navigation: implemented item_at_path, items_at_path,
path_exists?, path_of_item and path_unique? on PATHABLE (previously all
five raised NotImplementedError with no overrides anywhere in the gem).

* New OpenEHR::Path (lib/openehr/path.rb): a standalone parser for the
  openEHR archetype path syntax (e.g.
  /content[at0001]/data[at0002]/events[at0006]/data[at0003]/items[at0004,
  'Systolic']/value), supporting at-code and archetype-id node_id
  predicates and name-disambiguation predicates. Deliberately rejects
  relative paths, "//" wildcards, and numeric index predicates
  (InvalidPathError).
* Pathable gained a `path_attribute` declaration DSL and `path_children`,
  used to implement the five navigation methods generically via a
  child-enumeration protocol rather than per-class path logic.
  Declared across Composition, Section, Entry/CareEntry/AdminEntry/
  Observation/Evaluation/Instruction/Activity/Action/InstructionDetails,
  GenericEntry, History/Event, ItemTree/ItemList/ItemSingle/ItemTable,
  Cluster/Element, EHRStatus, and Folder.
* item_at_path raises the new PathNotUniqueError when a path predicate
  matches more than one sibling (e.g. a shared node_id needing a name
  predicate to disambiguate) - BREAKING: Pathable's five methods no
  longer raise NotImplementedError; any code catching that is affected.
* ItemTree#element_at_path / #has_element_path? now delegate to the real
  path machinery, so nested paths through CLUSTERs resolve correctly
  (previously only a top-level, non-recursive node_id comparison). The
  legacy bare-node-id calling form (e.g. element_at_path('at0002')) still
  works via a deprecated compatibility shim that normalizes it to
  /items[at0002].
* ItemTable#as_hierarchy already fixed in 1.3.1 (see below) to build a
  Cluster from all rows rather than just the first.
* History#events=, Composition#content=, and Cluster#items= now
  auto-wire each child's #parent to the containing object, fixing
  Event#offset (which relies on @parent.origin) for objects built the
  normal way instead of requiring callers to wire parent manually.
